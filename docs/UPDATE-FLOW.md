# 更新 UI 逆向核对与替换说明

## 安装版 v0.6.0 实际前端代码

对安装资源格式化/静态解析，不宣称取得原始 TSX 或后端源码。更新组件位于 `index-u_lcCyvf.js` 的 `vw`；以下行号是本机分析副本的行号。

1. 用户菜单管理员入口 `userMenu.checkUpdate` 打开弹窗（约 19300 行）。
2. 弹窗打开后触发查询：操作编号 `§12c5c3e863b3ed9d`，参数 `channel=stable|prerelease`（约 18716 行）。它走原版安全通道，并非我们仓库的版本源。
3. 通道值保存到 `localStorage/mmwx-update-channel`。切换只重新检查，不自动安装。
4. 检查结果包含 current_version/latest_version/has_update/release_notes/download_url/release_url/in_place_updatable/update_hint。
5. 有更新显示版本和说明。无更新显示“已是最新版本”和“强制重新安装”。
6. 更新使用 GET `/api/admin/update/apply-sse`，携带 `MM-Authorization`，参数含 channel、可选 force=true 和 target。
7. SSE 状态为 checking/downloading/backing_up/replacing/restarting，随后 done/error。进度条仅用于下载阶段。
8. done 后旧 UI 固定 3 秒刷新，没有等待服务恢复和校验实际运行版本。连接断开则显示错误。
9. 安装中的通道/重试按钮禁用。弹窗关闭不会取消已开始的后端安装。
10. 检查请求错误缺少明确错误分支：结果未定义也可能落入“已是最新版本”；“强制重新安装”在无更新分支未判断 in_place_updatable。

实际界面已在本机打开核对检查、版本、通道和重新检查；没有执行官方安装、重装或回滚。上述下载/安装阶段来自前端代码，不冒充官方后端实测。

## 本仓库 v0.2.0 的替换

- 保留用户菜单入口位置，文字保持为“检查更新”；支持中文和英文入口。原始页面、鉴权和许可证不改。
- 弹窗区分“预览运行版本”和“官方程序版本”。不再把官方的“最新”当作本项目最新。
- 公开仓库采用“检查新版本 → 下载签名 ZIP → 检查签名/目标版本/更新内容 → 安装 → 重启 → 等待恢复”。也支持手动导入。版本源固定为本仓库 GitHub Releases，无需 GitHub Token。
- 使用服务器独立维护口令 `runtime/update-key`，与 GitHub Token、官方登录密码分开。口令不写入仓库、URL 或浏览器持久存储。
- 更新包必须经项目 Ed25519 密钥签名；限制文件白名单、体积、版本递增和逐文件 SHA-256。不允许任意 ZIP/数据库/二进制覆盖。
- 应用前备份受管理代码和 SQLite 一致性快照。写文件失败恢复已替换代码。备份目录保持私有。
- 安装只显示“等待重启”。重启调用现有 systemd 服务；客户端最长 120 秒轮询，实际运行版本匹配且已完成启动才显示成功。没有假倒计时成功。
- 保留数据库、密钥、设置、主题和壁纸文件，固定官方程序 v0.6.0。拒绝代理转发官方 apply 接口，避免两套更新互相覆盖。上游直连端口也不应对公网开放。
- 不提供自动回滚承诺；重启失败保留备份，需要终端恢复代码并重启。后续可增加守护进程回滚。

## 导航修复

原版 `Topbar` 用 offsetWidth 估算可容纳项目数；菜单链接未显式禁止 flex-shrink。新增独立 CSS，固定链接的内容宽度，让原版“更多”逻辑计算实际宽度，防止挤压文字。没有改动原版编译资源文件，注入文件带版本号防缓存。

## 实测边界

本仓库测试涵盖签名验证、坏包拒绝、未授权拒绝、备份、文件替换失败恢复、状态分支、HTML 注入和禁用官方安装接口。Linux systemd 真正重启和服务器 Safari 环境需部署后验证；不能从本机测试推断所有原版业务通过。

本机验证：10 项自动测试通过，另在隔离预览副本操作用户菜单、签名包校验、安装和非 systemd 重启错误。公开下载须在发布后验证；Linux systemd 重启未在本机模拟为成功。

## v0.2.2 启动修正

服务器日志显示 v0.2.1 端口预检查 bind 报 EADDRINUSE，多次 systemd 重试后恢复。与连接关闭后的 TIME_WAIT 不可复用一致，但日志本身未记录端口和连接状态，因此不排除当时的实际监听冲突。修复预检查的 SO_REUSEADDR，并标出冲突端口；实际监听建立后才写监听日志。安装脚本轮询版本接口，确认目标版本后才报告成功。

本机实际官方二进制 + 网关连续启动/停止三次通过；首次空数据库启动超过旧版 30 秒预算，后端启动预算改为 90 秒，安装等待为 120 秒。共 14 项自动测试通过，包括 TIME_WAIT 后复用、真实监听冲突、目标版本/待重启状态判断和就绪超时失败。Linux systemd 调用仍需服务器验证。

- 首屏恢复标题、通道、检查结果、当前运行版本和重新检查；维护口令、签名 ZIP 导入默认收起。

- 14 项现有 Python 更新测试通过；JavaScript 语法检查通过。没有把静态/隔离测试称为 Linux systemd 全流程通过。

## 2026-10-27 更新流程审计（v0.2.6）

服务器提供的真实终端日志确认 v0.2.4 → v0.2.5 手动安装成功：最终 running/installed 均为 0.2.5，pending=false。重启期间短暂连接拒绝随后恢复，不能将中间重试当作最终失败。该目录没有 Git 元数据，旧的 git pull 操作不适用。

本次补强：

- CLI 与网页调用相同签名校验、备份、文件替换实现；新增 inspect/install 命令和 --latest/--restart 参数。
- 文件锁阻止不同进程中的 CLI 与网页同时安装；保留文件权限，待重启标记写入失败会恢复已替换代码。
- 网页网络请求设置超时，代理返回 HTML 时显示 HTTP 状态；安装或重启丢失响应时重新确认服务器状态。
- 安装完毕明确标为待重启，禁止再次安装。只有 running/installed 都匹配目标且 pending=false 才显示更新成功，超时显示未确认。
- 更新完成后重新获取菜单版本，安装脚本不再自动将维护口令输出至日志。
